## Planner Summary

Phase 04.1 proved host feasibility but did not create a product skeleton. Keep `clap/spike/`, `clap/build-capability`, and the capability bundle intact as regression evidence. Create the product under `clap/src/`, build it in `clap/build`, and give it a distinct bundle identity. The spike is reusable only as evidence and for a few narrow mechanics: bit-transparent audio copy, exact input-event offset forwarding, fixed-size atomic publication, bounded state decoding, parameter flags, and host GUI lifecycle expectations. Its monolithic raw CLAP plug-in, Cocoa implementation, placeholder status/action parameters, vector-backed test processor, and probe state identity are throwaway.

Three existing authorities remain canonical:

1. `daemon/src/runtime/boot.ts` is the only daemon composition root. Add the CLAP peer endpoint, registries, sessions, proposal services, and Stop coordinator there; do not create a second daemon.
2. Existing-state edits must traverse the service extracted from `daemon/src/query/query-server.ts`'s candidate/pre-flight/risk/inverse/controller/journal sequence. CLAP proposal dispatch must not duplicate or bypass it.
3. `bridge/src/main/java/com/bwbrain/bridge/PullHandlers.java` remains the only Bitwig mutation adapter. Phase 04.2 may add correlation/confirmation reads, but `apply.patch` remains the mutation seam.

Phase 04.1 supersedes two earlier recommendations: track/device names are hints only because live track-info returned an empty name, and D-03 follows the accepted Q3 evidence exactly. The Bitwig device panel uses read-only CLAP parameters for connection status, session status, and proposal-pending indication, plus ordinary automatable parameters for genuine musical controls such as Generated Mix. Analyze and Stop are hosted-editor-only non-recording actions and are never registered as automation parameters. Save As must be an explicit `session.fork`; Controller API 21 has no authoritative Save As signal.

### 3. Dedicated targeted peer endpoint

**Apply to:** `peer-server.ts`, `peer-connection.ts`, `peer-registry.ts` and tests.

**Reuse from:** loopback refusal and atomic-line write in `daemon/src/transport/tcp.ts:24-82,88-98`.

```typescript

if (host !== LOOPBACK_HOST) {
  throw new Error(`... refuses non-loopback bind ...`);
}
this.server.listen(this.port, this.host);

```

**Explicit anti-analog:** `TcpServerTransport.send()` lines 88-98 fans every message to every socket and `onMessage` erases socket identity. Never instantiate it for CLAP peers and never add a connection selector to the controller transport. Build a dedicated adjacent endpoint (research default `127.0.0.1:7879`) where accept assigns `connectionId`, each socket owns its own `LineBuffer`, bounds, handshake timer, outbound queue, and close cleanup, and the only send primitive is `sendTo(connectionId, envelope)`.

Observational telemetry may coalesce/drop-oldest with a visible counter; handshake, identity, approvals, arm, Stop, and phrase commands must never silently drop. Close on hard bound violations.

Required targeted-routing test: connect controller plus CLAP A and CLAP B; send a phrase to A; assert only A receives it, B and controller receive zero bytes. Also cover split lines, oversized line, invalid schema, queue overflow, handshake timeout, disconnect cleanup, reconnect, and non-loopback refusal.

### 6. Project, instance, link, focus, and fork registries

**Apply to:** `project-registry.ts`, `focus-registry.ts`, `peer-registry.ts`, `InstanceState.*`.

Keep these identities separate:

| Identity | Owner | Persistence | Transition |
|---|---|---|---|
| `connectionId` | peer registry | memory | new per socket |
| `instanceId` | daemon minted, CLAP persisted | plug-in state | closed lease resumes; simultaneous claimant rekeys |
| `projectId` | project registry | project-local durable state | explicit create/open/fork |
| controller link | daemon registry after controller confirmation | project-local durable state | unconfirmed → pending → confirmed → stale/unlinked |
| focused target | focus registry | memory/project UI state | explicit `(projectId, instanceId)` only |

Use the bounded Map lifecycle from `candidate-store.ts:48-106` for in-memory leases/focus, and atomic temp-in-destination-directory plus rename for durable project/link/fork records. Never reuse `CandidateStore` itself; candidates and approval grants have different ownership and invalidation rules.

The Phase 04.1 state probe proves only that copied state reproduces identity (`capability_probe_test.cpp:61-68`), which is why collision leasing is mandatory. Product `InstanceState` stores schema version, daemon-minted UUID, and musical settings with strict maximum state bytes. It must not store project conversation/history or accept a display name as authority.

Required state-machine tests: reconnect after closed lease resumes; simultaneous copy gets one rekey; stale/unconfirmed blocks Analyze/approve/apply/arm; focus changes are visible but never retarget a stored proposal; rename only changes hints; explicit fork copies lineage then produces divergent project/session histories; no implicit Save As fork.

### 8. Proposal revisions and atomic one-shot approvals

**Apply to:** `proposal-store.ts`, `approval-store.ts`, `proposal-dispatch.ts`.

Use `CandidateStore` as the role analog for daemon-minted opaque IDs, capped maps, and explicit eviction (`candidate-store.ts:66-76,88-106`). Do not copy its refresh-on-read or reusable-get semantics for approvals.

`ProposalStore` owns canonical immutable content and monotonically new revisions. Scope includes `proposalId`, `revision`, `kind`, `projectId`, `instanceId`, optional `clipSid`, rationale, assumptions, and bounded exact material. Any content or target change creates a new revision and invalidates grants.

`ApprovalStore.issue` mints a CSPRNG opaque token bound to canonical digest, revision, project, instance, optional clip, kind, and expiry. `consume` must atomically compare-and-delete before side effects; concurrent consumes yield exactly one success. Reject reuse, expiry, revision/content drift, focus/target mismatch, disconnect, Stop, rekey, and fork. Existing-edit consume delegates to `EditService`; live-MIDI consume creates one immutable targeted `ArmedPhrase` and never touches `PatchHistory`.

### 9. Native processor, RT queues, telemetry, scheduler, and ledger

**Apply to:** all `clap/src/rt/*`, `PluginProcessor.*`, `PeerClient.*`.

**Reusable spike mechanics:** `CapabilityProbeProcessor.h:43-47` provides bit-identical in/out copying; `CapabilityProbePlugin.cpp:107-141` preserves event headers and sample offsets through `try_push`; `CapabilityProbeEditor.h:17-55` demonstrates always-lock-free atomic snapshot publication. Copy the behavior into product-owned abstractions, not the probe classes.

```cpp
if (input == output) return;
for (std::size_t i = 0; i < count; ++i) output[i] = input[i];

const bool pushed = process->out_events->try_push(process->out_events, event);
// event->time is preserved

static_assert(std::atomic<std::uint32_t>::is_always_lock_free);
```

The audio callback may only copy original signal/events, update fixed aggregate accumulators, pop immutable bounded commands from an SPSC queue, schedule events, and update the generated-note ledger. No JSON, allocation, locks, logging, filesystem, socket/DNS, SDK calls, or UI callbacks.

Telemetry has a schema allowlist: bounded recent note events and fixed aggregates such as RMS/peak, note density, pitch-class/velocity/rhythm bins, and transport/tempo/time-signature flags. PCM/raw audio buffers, sysex retention, FFT frames, and arbitrary histories are forbidden. Overflow coalesces/drops observational snapshots and increments a visible counter; it never blocks RT.

`PhraseScheduler` is a pure allocation-free state machine. It accepts only immutable daemon-authorized phrases, waits when transport flags are insufficient, recomputes after jump/loop, calculates exact next beat/bar sample offset, and merges generated/output events in sample order while preserving all original events. Push failure cancels remaining generated behavior and requests bounded cleanup.

`OwnedNoteLedger` keys generated phrase ID + note ordinal + exact CLAP port/channel/key/note_id. Disconnect, Stop, transport stop, reset, deactivate, and output failure cancel future generated events and emit owned note-offs when processing is available. Never suppress or synthesize cleanup for input-owned notes. Disconnect must remain transparent dry pass-through.

### 10. Hosted workspace and musical parameters (Research Pattern 7)

**Apply to:** `PluginEditor.*`, `UiState.h`, editor/component tests.

The probe's GUI callback shape at `CapabilityProbePlugin.cpp:253-295` is host-lifecycle evidence only. Use JUCE through the pinned adapter for product Cocoa/Win32/X11 hosting. The UI renders immutable main-thread snapshots and enqueues worker commands; it never reads sockets or RT objects directly.

Required view contract: compact context/focus strip; central project conversation; proposal drawer absent when no inspectable proposal exists; connection/link/session/analyzing/error states; explicit project/track/instance scope; proposal revision/material; approve/arm state; next beat/bar countdown; telemetry health. Per superseded D-03 and accepted Phase 04.1 Q3 evidence, connection status, session status, and proposal-pending indication are read-only non-automatable CLAP parameters in the Bitwig device panel. Genuine musical controls are ordinary automatable CLAP parameters and cross to RT through atomics/parameter facilities. Analyze and Stop are always available as hosted-editor-only non-recording worker actions; they are never CLAP parameters and never enter automation. The hosted editor is the richer workspace, not a substitute for the required device-panel status/pending/musical surface.

### 11. Global Stop

## Shared Patterns

### Validate at every boundary

**Source:** `daemon/src/protocol/reader.ts:32-67,175-204`  
**Apply to:** peer ingress, Pi tool output, proposal creation, approval consume, phrase decode, controller response. Parse in try/catch, validate before dispatch, reject unknown discriminants/fields, and never log sensitive/full musical payloads.

### Bounded ownership

**Source:** `candidate-store.ts:26-76`; `reader.ts:98-173`; `MidiOffsetMeasurement` fixed atomics.  
**Apply to:** connections, queues, telemetry, conversation chunks, proposals, approvals, phrases, notes, cleanup work. Bounds must exist in schemas and code and have limit+1 tests.

### Explicit degradation

**Source:** `query-server.ts:464-515` and `PullHandlers.java:132-159`.  
**Apply to:** unconfirmed identity, missing transport flags, stale controller link, disconnected daemon, unavailable metadata. Surface the degraded state; never infer authority or silently proceed.

### Durable versus ephemeral state

**Source:** `candidate-store.ts:3-14`; `patch-history.ts:61-110`; atomic-write discipline.  
**Apply to:** project/link/fork/Pi lineage are project-local durable state; connection leases, focus, active turns, approvals, and armed phrases are ephemeral. Plug-in state is instance-local identity/settings only.

### Error handling

**Source:** `query-server.ts:435-446,745-789`; `PullHandlers.java:207-240`.  
Expected refusal states return structured errors. Transport/peer failures do not crash the daemon. Never journal partial/failed controller mutations. RT failures become bounded state flags/cleanup commands, never exceptions or logging on the audio thread.
