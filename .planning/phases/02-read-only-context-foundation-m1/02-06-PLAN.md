<objective>
Close the Phase-2 UAT blocker diagnosed in `.planning/debug/extension-load-deprecated-getchannel.md` and recorded as the single `severity: blocker` gap in `02-UAT.md` (Test 1): the production bridge fails to load inside Bitwig 6.0.6 because `trackBank.getTrack(i)` at `Observers.java:139` invokes a Bitwig Control Surface API method deprecated since API v2, and Bitwig 6.0.6 enforces deprecation-as-error at runtime (aborting `init()` so no events ever round-trip).

Purpose: This is a knowledge-loss regression — Phase 1 already documented that `TrackBank.getTrack(int)` / `getChannel(int)` are BOTH deprecated in API 21 and deliberately avoided TrackBank in the spike; Phase 2's bridge re-introduced the call with an inline comment that directly contradicts the known constraint. Autonomous verification passed because `javap` checked the WRONG invariant (method presence) instead of the right one (method non-deprecation). The fix is therefore four-pronged: (1) the one-line code correction to the terminal non-deprecated accessor, (2) comment + doc corrections so the knowledge loss cannot recur a third time, (3) a process-gate script that mechanically flags deprecated Bitwig call sites at verification time (closing the javap-vs-deprecation gap), and (4) a live reload proof that the blocker is actually gone — because the whole point of this gap is that autonomous verification lied once already.

Output: A rebuilt `bridge/target/bw-brain.bwextension` that loads cleanly in Bitwig 6.0.6; corrected `Observers.java` + `docs/bitwig-capabilities.md` comments/docs; a new `scripts/check-deprecated-bridge.mjs` gate wired into verification; a captured live load + round-trip observation.
