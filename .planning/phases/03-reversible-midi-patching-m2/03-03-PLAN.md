## Phase Goal

**As a** producer, **I want to** generate motif-preserving MIDI variants, **so that** creative transforms never degrade into "casino MIDI" — below-threshold refuses rather than guesses.

## Plan Objective (vertical slice 3: musical knowledge foundation)

Plan 01 shipped the trust-spine primitives; this plan ships the **musical-reasoning foundation** the transforms (Plan 04) lean on: motif signature (MIDI-01), harmonic-center detection (D-12), and the genre-profile interface (ARCH-01/02). After this plan: the daemon computes motif signatures, detects harmonic centers (refusing below bar), and resolves genre profiles — all pure, all tested, all registered in the D-08 analyzer framework. This plan is **parallel with Plan 02** (zero file overlap — Plan 02 owns patch/* + cli/commands/edit.ts + query-server + bridge; this plan owns transforms/* + profiles/* + analyzer-registry + the motif analyzer).

**Purpose:** MIDI-01 (motif signature + preserve-motif mode), ARCH-01 (genre-profile interface), ARCH-02 (generic core runs without a profile).
**Output:** motif-signature.ts, harmonic-detect.ts, profile-loader.ts, generic.json, techno.json, profile.schema.json consumption, analyzer-registry M2 extension.
