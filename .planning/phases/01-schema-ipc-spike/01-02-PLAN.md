    Build the transport-agnostic framing primitives that make the kept scaffolding reusable regardless of which transport wins (D-05 core). All .ts files use ESM exports and .js extensions on relative imports (NodeNext).

    transport.ts (interface — transcribe RESEARCH.md Pattern 1): export interface Transport with onMessage(handler: (chunk: unknown) => void) registration, send(msg: object) that throws on unrecoverable write failure (never silently swallow — edits must be acked or errored), and close(). The reader consumes ONLY this interface, never a raw net.Socket directly — that is what makes TCP/stdio swappable.

    tcp.ts (TcpServerTransport implementing Transport): construct with {host, port}. SECURITY INVARIANT (Pitfall 5, the single security-relevant decision in the spike): bind the loopback address only — pass the literal loopback IP string as the second argument to net.createServer().listen(port, host). NEVER omit the host argument and NEVER bind the all-interfaces wildcard (the address whose dotted-quad is four zero-octets) — doing so would expose the daemon to the LAN and break the local-first trust model. On a socket 'connection', pipe 'data' events into the registered onMessage handler as the chunk. send does ONE socket.write call of JSON.stringify(msg) concatenated with a single newline (atomic-line write, Pattern 4 — JSON.stringify already escapes embedded newlines so one write = one line; never split a message across writes). Handle 'error'/'close' by cleaning up. The transport does NOT parse JSON — that is the reader's job; it only moves bytes.

    stdio.ts (StdioTransport implementing Transport): the documented fallback (AGENTS.md line 125; RESEARCH.md Transport Decision Rule outcome #3). onMessage reads process.stdin chunks; send writes JSON.stringify(msg) + newline to process.stdout in a single write (atomic-line, Pattern 4); close calls process.stdin.destroy(). Do not over-invest — it exists so the reader scaffolding is provably transport-agnostic (D-05).

    line-buffer.ts (transcribe RESEARCH.md Pattern 2 verbatim): export class LineBuffer with a private string buffer, a constructor taking an onLine callback, and feed(chunk: string | Buffer). feed appends (coercing Buffer to utf8), then loops splitting on the newline character: for each complete line, strip a trailing carriage-return if present (tolerate the jsonlines.org CRLF form), and if the line is non-empty call onLine(line). Retain any trailing partial fragment in the buffer for the next feed. feed is PURE framing — no JSON.parse, no validation here; that happens in the reader. JSDoc cites jsonlines.org.

    handshake.ts: export a pure function negotiateVersion(theirVersion: string, ourVersion: string) returning an object {ok: boolean, serverVersion?: string}. Rule (Pattern 3): compare MAJOR versions (the integer before the dot); equal major => ok true, serverVersion set to ourVersion; different major => ok false (reject — prevents protocol-drift silent corruption, RESEARCH.md §Security). This pure function is unit-testable without sockets (Plan 02 Task 2 + handshake.test.ts). Keep it framework-free.
