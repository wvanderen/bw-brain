Implement `energy-curve.ts` as a PURE module + Analyzer plugin.

1. **Pure helpers**:
   - `normalizeAgainstPeak(values: number[]): number[]` — linear division by `Math.max(...values, 1e-9)` (zero-guard, mirrors `motif-signature.ts:80` `|| 1`). Returns values ∈ [0,1] with peak ≈ 1.0 (exact 1.0 unless all-zero). (D-16)

     - Default `beatsPerBar = 4` (4/4 time; the project timeSignature could override but the daemon passes it via ctx — keep 4 as the pure-function default).
     - For each scene in index order: compute TRUE per-bar energy (D-17 — per-bar within the launched sequence, not scene-aggregate repeated). For each bar `b` within the scene (bar count = `ceil(scene.loopBeats / beatsPerBar)`): filter the scene's active cells' notes to those whose `start` falls in the bar's beat range `[sceneStart + b·beatsPerBar, sceneStart + (b+1)·beatsPerBar)`, then compute the weighted composite `weighted = w1·noteDensity + w2·velocityAggregate + w3·polyphony + w4·pitchCentroid` from THAT bar's filtered notes (re-derive the four signals per bar; do not reuse the scene-aggregate feature vector). This delivers genuine intra-scene energy variation — a 16-bar scene gets 16 distinct points, not one stepped value. For scene counts ≤ 64 this is trivially cheap (the notes are already in memory from the snapshot).
     - Collect all per-bar raw values; `normalizeAgainstPeak`; emit `{bar: <global bar index>, value}` points. Empty scenes contribute zero-value points (the producer sees the gap). (D-17)
     - Global bar index increments across scenes in order (scene 0 bars 0..k-1, scene 1 bars k..2k-1, etc.).

  <action>
Implement `track-role-classifier.ts` as a PURE module + Analyzer plugin.

1. **Per-track feature aggregation `aggregateTrackFeatures(trackSid, grid)`**: for a given track, gather all notes across its hasContent cells. Compute (reuse Plan 02 / motif-signature primitives):
   - `registerDistribution`: 128-bin MIDI pitch histogram (normalized to sum=1) — velocity-weighted.
   - `rhythmPattern`: 5-bin IOI histogram (normalized) — bin edges at [0.25, 0.5, 1.0, 2.0] beats (the motif-signature IOI pattern).
   - `velocityProfile`: {mean, variance} across all notes (velocity / 127).
   Return `TrackFeatures`. Tracks with zero hasContent cells → return null (filtered out per RESEARCH Open Question 4).

2. **Pure template-matcher `classifyTrackRole(features: TrackFeatures, templates: RoleTemplate[], weights?): RoleClassification`** (D-08/D-18):
   - Weights default `[0.4, 0.4, 0.2]` over `[register-masked, rhythmProfile, velocityProfile-3-vector]`.
   - For each template: 
     - **Register-masked scoring**: zero out `registerDistribution` bins outside `[registerLow, registerHigh]`; renormalize; compute cosine between the masked distribution and a uniform-in-window reference (a track with notes spread evenly in the window scores highest). Use `cosineAffinity` from Plan 02's self-similarity.ts OR the motif-signature cosine.
     - **Rhythm scoring**: cosine between `features.rhythmPattern` and `template.rhythmProfile` (both 5-bin normalized).
     - **Velocity scoring**: cosine over 3-vector `[mean, variance, sqrt(variance)]` between features and template (small variance → tight match).
     - Weighted sum → `score ∈ [0,1]`.
   - Sort templates desc by score. `bestScore = scores[0]`. If `bestScore ≥ template.minConfidence (default 0.5)` → `role = bestTemplate.role`. Else → `role = "unknown"`. 
   - `confidence = bestScore` (honest ∈ [0,1]; do NOT pre-floor — Pitfall 4).
   - `alternatives = scores.slice(1, 4).map(s => ({role, score: s.score}))` (top 3 runners-up).
   - If role="unknown", add an `assumption: "no template cleared <minConfidence>"` field.
   - Return `{trackSid, role, confidence, alternatives, assumption?}`.

3. **Analyzer wrapper `TrackRoleClassifier`**: `id: "trackRoles"`, `consumes: ["clips"]`, `produces: ["trackRoles"]`. In `analyze(raw, ctx)`: extract grid; for each track with ≥1 hasContent cell: `aggregateTrackFeatures` → `classifyTrackRole(features, ctx.profile.roleTemplates ?? [])`. Collect into `Record<trackSid, RoleClassification>`. If no tracks classified → `[]`. Else return `[{field:"trackRoles", value: classifications, confidence: meanConfidence, assumptions: [...]}]`. (The persistence to roles.json happens in Plan 05's query-server handler — this analyzer emits the classification; Plan 05 writes it.)

NodeNext ESM `.js` imports; type-only back-import.
