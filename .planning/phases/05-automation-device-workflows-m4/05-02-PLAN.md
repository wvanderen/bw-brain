<objective>
Phase user story: **As a** producer, **I want to** know exactly how Bitwig records automation writes before the companion is allowed to write any, **so that** it never guess-writes or silently no-ops.

This plan runs the LOCKED in-phase live probe (D-05-05, D-05-06) that gates the entire write wave. It is a blocking human-verify checkpoint pattern on prior-phase precedent (Phase 1 Track A JS probe for iteration speed; Phase 04.1 evidence gates): the agent prepares a throwaway probe script and an evidence template; the human runs the matrix against live Bitwig; the agent transcribes the results into docs/bitwig-capabilities.md as dated Observed fields BEFORE 05-05/05-06 implement the refusal gates and bridge write path.

Probe question set (RESEARCH §Open Questions 1-3 + Pitfall 2/6): touch+set behavior under {playing, stopped} × {automation-write armed, not armed}; whether envelope points appear ahead of/behind the playhead; set vs setImmediately vs setRaw differences; clip-launcher vs arranger write targets; whether set(double) is normalized [0,1] (A1); getParameter(i) full-list vs page indexing + realistic VST param count (A2); which remote-page creation site surfaces the producer's macro knobs.

Purpose: pin write semantics with honest evidence; derive the named-refusal vocabulary.
Output: probe artifact, corrected + dated capabilities doc sections, refusal vocabulary table.
</objective>
