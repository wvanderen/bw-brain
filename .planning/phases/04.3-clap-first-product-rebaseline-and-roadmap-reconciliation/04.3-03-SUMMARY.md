## Decisions Made

- New UiEvent variant `ConversationChunkReceived{requestId, sequence, text}` carries the contiguity decision into the reducer rather than computing final text in the decoder — the snapshot read + mutation stay inside the store's copy-on-write lock (no TOCTOU between decoder snapshot() and reduce())
- analysis.complete treats a missing/mismatched requestId as "no chunks delivered" and keeps the existing AnalysisChanged path — existing tests and the error enum surfacing are untouched
- Encoder emits `refresh` always (true/false literal) rather than omitting it when false — explicit wire honesty; both forms validated against the schema (refresh is optional but never ambiguous)
- Duplicate sequence-0 retransmission resets to the resent chunk (idempotent for the same text) — simplest rule that never stitches
