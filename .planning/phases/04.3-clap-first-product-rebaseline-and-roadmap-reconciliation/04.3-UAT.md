## Findings: detection-failure root-cause chain (2026-08-21)

Three pre-existing Phase-04 defects surfacing at this phase's acceptance boundary. Recorded for gap-closure planning (`/gsd-plan-phase 4.3 --gaps`) — to be consumed verbatim.

1. The Review/Analyze evidence rendered correctly (all five dimension groups present, pulledAt on every group, assumptions lines, honest empty-state placeholders) — the render/readability/scroll/refresh mechanics PASSED.
2. But every detection dimension was EMPTY: 0 scenes, no sections, no repetition, no energy, no track roles. Root cause is NOT the new CLAP path — the persisted snapshot (`daemon/.bw-brain/arrangement-snapshot.json`) contains a launcher grid where tracks 4–7 have EMPTY trackSids and ALL 128 cells read `hasContent:false` (placeholder `clip_0000000000000000`). The bridge's `get.launcher_clips` walk read the grid before Bitwig's track/slot banks synced, and/or the walk exceeded the daemon's 3000ms pull timeout (daemon logs show repeated "bridge get.launcher_clips timed out after 3000ms" plus correlator "unsolicited response for unknown id ... dropping" — late responses arriving after timeout).
3. The partial/invalid snapshot (empty trackSids violate arrangement-snapshot schema `minLength:1` on tracks 4–7) was PERSISTED to disk — the write path did not validate what it saved.
4. A subsequent CLAP `arrange.review` crashed the daemon: `handleArrangeReview` → `prepareArrangeDispatch` → `loadArrangementSnapshot` threw the schema-validation error unhandled → process exit (Node.js v22.22.3 stack, `daemon/src/state/arrangement-snapshot.ts:246`, `query-server.ts:1114/1208`). Boot path logs the invalid file and continues; the query path throws fatally.
5. Clip-level selection works: an Analyze turn on the selected launcher clip `clip_d4e046de700123bd` produced a correct `existing_edit` proposal (`prop-44cf6114-existing-017` r1, patch `pt_fa343d1f`) with correct scope, assumptions, and advisory discipline — so the confirmed-scope → Pi → proposal-drawer path is healthy.

Defect classification:

- **DEFECT A (bridge/daemon):** launcher grid pull race — walk reads banks before sync; empty trackSids + `hasContent:false` persisted; walk exceeds 3000ms timeout and late bridge responses are dropped by the correlator.
- **DEFECT B (daemon):** snapshot write path persists schema-invalid content (no validation on save).
- **DEFECT C (daemon):** `loadArrangementSnapshot` throw is unhandled on the arrange.review path — one bad snapshot file crashes the daemon (boot is resilient, query path is not).
- **DEFECT E (daemon, found 2026-08-22 attempt 4):** populated analyzer results were assigned directly into the narrower strict durable snapshot shape. `RoleClassification.trackSid` (and optional `assumption`) plus `SectionSummary.energy` caused validate-before-persist to reject otherwise valid populated launcher snapshots. Empty-scene automated refresh coverage never exercised these analyzer outputs. Fixed by explicit boundary projection plus a populated-grid regression.
- **DEFECT F (daemon renderer, found 2026-08-22 attempt 5):** `sceneCountOf(sections)` rendered `Timeline (0 scenes)` whenever section labels fell below confidence, even when track roles, energy bars, and repetition proved populated scenes. The energy group likewise said no energy solely because `sections` was empty. Fixed by carrying snapshot `sceneCount` authoritatively and keeping independent per-bar energy visible; regression covers populated evidence with zero accepted sections.
- **DEFECT G (bridge settle gate, found 2026-08-22 attempt 6):** bank observation count is cumulative for the controller lifetime, but the sync threshold was the absolute constant 152. After initialization it remained permanently satisfied, allowing Review to walk the launcher cache mid-project-switch before the correct `hasContent` callbacks settled. Fixed with a request-relative threshold plus a regression starting from lifetime count 300 and proving the request waits the 250ms quiet window.
- **DEFECT H (daemon link scope, found 2026-08-22 attempt 7):** a selected track outside the fixed 8-row summary bank could not be reconciled even though the controller correlation response carried its cursor track hint. Fixed with an out-of-window cursor-selected-track fallback; in-window summary names remain preferred.
- **DEFECT I (daemon peer identity, found 2026-08-22 attempt 7):** `inst-local` was treated as reusable whenever no simultaneous live claimant existed, allowing a newly inserted plug-in to inherit a historical confirmed project link. Fixed by always rekeying the construction sentinel during handshake; the existing CLAP rekey/persistence path consumes the daemon-minted ID.
- **DEFECT J (bridge launcher capture, found 2026-08-22 attempt 8):** request-relative thresholding alone did not prevent an old `lastObservationAt` from satisfying quiet at t=0 before a new project callback burst began, and cache-only reads could lag the subscribed Bitwig value. Fixed by enforcing a per-request 250ms minimum and reading each already-subscribed slot's live BooleanValue during the walk, with cached state as fallback.
- **DEFECT K (bridge cursor-ready signal + bank width, found 2026-08-22 attempt 9):** selection readiness relied solely on a `loopLength` value-change callback; consecutive clips with equal lengths emit no change, so real populated cells timed out and were rewritten empty. The production adapter now uses the cursor's positive current loop length on timeout for a slot already proven populated. The fixed bank width of 8 also omitted ninth-track Lead; widened to 16 with existing phantom-tail trimming preserved.
