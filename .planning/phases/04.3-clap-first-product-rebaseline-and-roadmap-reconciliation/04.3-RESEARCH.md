## Summary

Phase 04.3 is a reconciliation phase, not a greenfield build. Phase 04.2 (completed 2026-08-20, 11/11 plans, 6/6 verification truths, live two-mode Bitwig 6.0.11 UAT) already delivered and verified every authority seam this phase builds on: confirmed-scope peer routing, the proposal/approval/consume lifecycle, the controller-owned EditService/journal path, daemon-managed Pi 0.84.0 sessions with four bounded tools, and a hosted JUCE editor whose proposal drawer is live-verified as "responsive, wrapped, and vertically scrollable" (commit `e8887b4`, 04.2-UAT.md observation). The top-level planning docs (PROJECT.md, ROADMAP.md, REQUIREMENTS.md, STATE.md) were already rebaselined on 2026-08-20; the residual drift lives in **generated and secondary docs** (`.claude/AGENTS.md` still says "Pi/OpenClaw package is the first-class UX" and "no cloud/remote model calls"), the **untracked legacy `04-UAT.md`** (14 pending tests, never executed, not in git), and the **arrangement analyzers' absence from the CLAP surface** (today they are reachable only via `bw-arrange` CLI over the UDS query channel).

The one substantive engineering slice is RB-03/UX-03: surfacing arrangement intelligence in the hosted editor. The critical technical findings: (1) the `conversation.chunk` telemetry message (≤512 chars, sequence 0–65535) exists in the frozen schema and has a C++ reducer, but **the daemon never emits it** — an unused, already-designed seam; (2) the conversation pane is a `juce::Label` (not scrollable, not wrapped) while `proposal_` is a `juce::TextEditor` with the exact verified wrap+scroll configuration — the locked "long content must be readable" decision maps directly onto converting `conversation_` to the already-proven TextEditor pattern; (3) `resolveAnalysisContext` (boot.ts:461) currently sends only project + selected-clip notes to Pi — arrangement-derived evidence is not yet part of confirmed analysis context; (4) arrangement evidence is deterministic analyzer output, so per the locked local-first decision ("Non-AI inspection and control continue to work without a remote provider") its rendering must NOT require a Pi turn — the Pi `create_proposal`-per-turn contract applies only when observations are escalated into exact-scope proposals.

**Primary recommendation:** Treat the phase as five plans matching the CONTEXT's Planning Targets: (1) documentation/operator reconciliation (regenerate AGENTS.md from PROJECT.md, dated supersession wording in pi-pack/README.md, classify-but-never-falsify legacy 04-UAT.md); (2) daemon arrangement read-model — a provider-independent, confirmed-scope-gated arrangement review path that reuses the `arrange.*` analyzer stack and emits bounded `conversation.chunk` sequences (no schema change required); (3) readable CLAP presentation — `conversation_` Label→TextEditor using the exact `e8887b4` drawer configuration; (4) legacy UAT classification + focused CLAP arrangement UAT ledger mirroring the 04.2-UAT shape; (5) Phase 5 implementation contract (a DOWNSTREAM-PLAN-NOTES-style document naming the patch-schema automation-operation extension as Phase 5's principal new dependency).

### Pattern 1: Bounded text evidence over the existing `conversation.chunk` seam
**What:** `telemetry.schema.json` already defines `ConversationChunk` (`{type, requestId, sequence 0–65535, text ≤512}`) and `UiState.cpp:302` already reduces it — but grep proves the daemon never emits it. [VERIFIED: codebase grep — daemon emits none]
**When to use:** deterministic arrangement review rendering with zero schema churn.
**Constraints:** current reducer REPLACES `UiState.analysis` per chunk (`AnalysisChanged{text}` → `next->analysis = value`); a multi-chunk review (>512 chars total is guaranteed — the `/review` ASCII render runs 1–2 KB) needs either append-on-sequence-continuity semantics in the reducer or a single bounded render. Sequence gaps must be handled honestly (reset, not stitch). [VERIFIED: UiState.cpp:133, 302–305]

### Pattern 2: Readable long content = the live-verified drawer configuration
**What:** commit `e8887b4` made the proposal drawer "responsive, wrapped, and vertically scrollable while retaining scroll position" during 04.2 UAT. [VERIFIED: 04.2-UAT.md live observations] The exact configuration is in `PluginEditor.cpp` on `proposal_`: `setMultiLine(true, true)` (word-wrap on), `setReadOnly(true)`, `setScrollbarsShown(true)`, `setCaretVisible(false)`, dark background/transparent outline.
**Apply to:** `conversation_` is currently a `juce::Label` (`PluginEditor.h`: `juce::Label context_,conversation_,status_;`) — Labels are single-line-oriented and cannot meet the locked "wrapping plus vertical scrolling" decision. Convert `conversation_` to `juce::TextEditor` with the drawer configuration verbatim. [VERIFIED: PluginEditor.h; ASSUMED for Label limitation semantics — mitigated by the fact that Phase 04.2 needed the TextEditor fix for readability]

### Pattern 3: Confirmed-scope gating for every new ingress
**What:** `ActionDispatch.dispatch` revalidates every action against daemon scope (`requireConfirmedScope` + `sameScope`) before side effects; unconfirmed scope → `action.error scope_not_confirmed`. [VERIFIED: action-dispatch.ts:35–40]
**Apply to:** any arrangement review request from the editor — same gate, same failure surface. The bridge pull for a fresh grid (`get.launcher_clips` via correlator) is read-only and authority-neutral.

### Pattern 4: Advisory discipline is grep-enforceable
**What:** `suggestTransitions` output (`TransitionObservation`) structurally carries NO patchId/operations/risk; query-server comments name the grep as the T-04-16 code-review check; the module is pure and must not import `../patch/*`. [VERIFIED: transition-suggest.ts:11–18, 44–58; query-server.ts:817–819]
**Apply to:** the CLAP render path inherits this — an arrangement review render must never mint a patch; escalation happens only through Analyze→`preview_edit`→`create_proposal` (kinds `existing_edit`/`live_midi` only).

### Pattern 5: Frozen-schema discipline if anything is extended
**What:** any new/changed message requires: schema edit → `npm run gen:types` → committed generated output → golden fixtures → C++ bounded decoder + limit+1 negative tests → drift gate (`git diff --exit-code -- daemon/src/gen/clap.ts`). [VERIFIED: 04.2-PATTERNS.md Pattern 2, validate-clap-product.sh]
**Apply to:** choosing the `conversation.chunk` reuse path avoids this entirely — a strong reason to prefer it for this phase.

## Common Pitfalls

### Pitfall 1: Forgetting the Pi turn's create_proposal contract
**What goes wrong:** an arrangement Analyze turn ends without a proposal → `pi_proposal_required` → surfaced as `analysis_proposal_required` error; producers see a "failed" review.
**Why:** `analyzePrompt` mandates exactly one `create_proposal` per turn and the session manager enforces it (project-session-manager.ts:100–104).
**How to avoid:** deterministic evidence rendering stays outside Pi; Pi turns remain proposal-producing by design. If arrangement context is added to `resolveAnalysisContext`, the prompt contract stays unchanged.
**Warning signs:** UAT rows where "Review" fails when no provider is configured (violates local-first) or Analyze turns erroring with `analysis_proposal_required`.

### Pitfall 2: Multi-chunk text stitching corrupts the conversation pane
**What goes wrong:** each `conversation.chunk` currently REPLACES `UiState.analysis`; naive multi-chunk sends show only the last 512 chars; out-of-order or dropped chunks silently stitch wrong text.
**How to avoid:** explicit reducer semantics (append while `sequence` is contiguous; reset on gap or new `requestId`); schema bounds already cap sequence at 65535; add limit+1 and gap tests. Alternatively render one bounded block ≤512 — insufficient for five-dimension evidence, so plan for append semantics.
**Warning signs:** editor shows only the tail of the review; no test for sequence gaps.

### Pitfall 3: Regenerating AGENTS.md by hand-editing
**What goes wrong:** direct edits to `.claude/AGENTS.md` are overwritten by the next GSD sync; the stale "Pi first-class UX" + "no cloud/remote model calls" wording survives.
**How to avoid:** fix source docs (PROJECT.md/STACK sections) and regenerate; verify by grepping AGENTS.md for the contradictory phrases afterward.
**Warning signs:** AGENTS.md still contains "A Pi/OpenClaw package is the first-class UX" or "no cloud/remote model calls" post-phase. [VERIFIED: these strings exist today at .claude/AGENTS.md lines 7, 16]

### Pitfall 4: Scope-creep into Phase 5 implementation
**What goes wrong:** the Phase 5 "contract" plan starts implementing automation operations or device enumeration.
**Why:** the temptation is real — the contract document will name patch-schema automation primitives (currently MIDI-note-only: `add_note`/`remove_note`/`update_note_field`) as Phase 5's gap.
**How to avoid:** 04.3 delivers a DOWNSTREAM-PLAN-NOTES-style document only; the patch schema, `preview_edit` parameter enums, and `cursorDevice.getParameter(int)` fallback stay untouched.
**Warning signs:** plan tasks editing `schemas/patch.schema.json` or `PREVIEW_EDIT_PARAMETERS`.

### Pitfall 5: Arrangement evidence without freshness honesty
**What goes wrong:** rendered evidence omits `pulledAt`/staleness; producer acts on a stale grid.
