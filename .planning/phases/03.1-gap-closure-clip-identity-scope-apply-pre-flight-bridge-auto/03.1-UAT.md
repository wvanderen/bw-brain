## Observations (non-blocking, out-of-scope for Plan 06)

<!-- Captured during UAT reverify — worth tracking as future-phase candidates. NOT UAT failures, NOT Plan 06 regressions. -->

- **Launcher-cursor-clip selection model is brittle for producer-driven testing.** The bridge creates a LAUNCHER cursor clip (`bridge/src/main/java/com/bwbrain/bridge/BridgeExtension.java:67` — `createLauncherCursorClip(64, 128)`), so `state.selection.clipSid` only updates when Bitwig fires `clip.name_changed` for the launcher cursor — i.e. when the producer launches/selects a clip slot in the launcher GRID. Clicking clips in the ARRANGER timeline, clicking SCENES, or re-clicking the same launcher slot does NOT fire the event. Observed during this UAT: the producer changed GUI selection many times (timeline + scenes + grid) but `state.selection.clipSid` updated unreliably (changed once across ~12 attempts). This makes producer-driven UAT of wrong-clip-targeting scenarios fragile.
  - **Impact:** Testing any feature that depends on `state.selection.clipSid` changing requires either (a) reliable launcher-slot double-clicks, or (b) a programmatic selection driver. Neither is currently available.
  - **Candidate follow-ups (future phase):**
    1. **Arranger cursor clip** — add a second `PinnableCursorClip` over the arranger view in the bridge so timeline selections also update `state.selection.clipSid`. (Bitwig API permits this; the bridge currently only wires the launcher cursor.)
    2. **Test-driver CLI** — the producer requested "a CLI working for changing selected clips for testing purposes." The Bitwig `PinnableCursorClip` API is read-only from the extension side (the extension cannot programmatically pin it to a slot), so this would require either (a) driving Bitwig via its keyboard-shortcut/OSC surface from outside the extension, or (b) a daemon-side `state.selection.clipSid` override for UAT-only purposes (gated behind a `--uat-override` flag, never enabled in production).
  - **Severity for THIS phase:** NONE — Plan 06's D-06 surface is CLI-side and verified via Test 4 live. This observation is about the bridge's selection-tracking surface area, which is a Phase 1/2 architectural choice.
