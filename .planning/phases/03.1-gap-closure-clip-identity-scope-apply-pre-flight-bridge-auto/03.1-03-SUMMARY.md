## Decisions Made

- **Pitfall 8 (single function) over parallel function:** the planner's RESEARCH §D-04 note floated two options for the wrong_clip_targeted shape: (a) extend `safeSendErr` with an optional details arg, or (b) add a sibling `safeSendDetailedErr`. (a) is shipped — one function, one shape family, one place to audit. The 11 existing safeSendErr callers needed zero changes (their details is undefined, so availableFrom:'M2' is preserved by the `...(details ?? { availableFrom: 'M2' })` spread).
- **Pre-fix migration via caveats, not refusal:** RESEARCH §D-05 Discretion resolved the migration policy question — pre-fix candidates/entries proceed with surfaced assumptions rather than hard refusal. Refusing would remove the recovery path with no alternative (Bitwig native undo is unreliable per docs/bitwig-capabilities.md §1; the producer may still be on the right clip by luck). The caveat surfaces honestly so the producer can abort manually.
- **Empty-string fallback for previewClipSid:** mint's signature is `previewClipSid: string = ""`. When `state.selection.clipSid` is unset (pre-Plan-02 state) the daemon passes "" and the gate treats it as a pre-fix candidate (caveated path). This avoids a separate code path for the disconnected-bridge fold case.
- **clipSid stamped on the revert-of-revert entry:** the apply-time entry carries clipSid (D-05 input), AND the revertEntry (which records the revert) also carries clipSid: liveClipSid. Reverting-the-revert re-validates against the same cursor clip — symmetric trust-spine.
- **Polling driveAsync over fixed drains:** the original `setImmediate` drain worked for midi.* (no disk I/O in their flow) but failed intermittently for edit.* under full-suite load (patchHistory.append delays transport.send). The 1s polling window is generous and robust; midi.* tests still pass under the same helper.
- **Task 3 auto-approve:** per `auto_advance: true` + `human_verify_mode: "end-of-phase"`, the live-Bitwig checkpoint is deferred to the end-of-phase UAT. The 6 automated gate tests are the load-bearing evidence (applyCalls() === 0 proves the gate fires before the bridge). Live-Bitwig validates Assumption A2 (clipSid reads reliably on a real cursor clip) — structurally already proven by Plan 03.1-02's ClipSidTest JUnit tests on the bridge side.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] driveAsync timing flakiness under full-suite load**
- **Found during:** Task 2 GREEN full-suite run (the gate tests passed when run in isolation via `-t wrong_clip` but failed when run as part of the full 39-file suite)
- **Issue:** The original driveAsync helper used `2x setTimeout(0) + setImmediate` to drain the async handler's microtask + macrotask queue. Under full-suite load, patchHistory.append's disk I/O (mkdir + appendFile + stat) delayed transport.send beyond those fixed drains, leaving transport.sent empty when the assertion fired.
- **Fix:** driveAsync now polls `transport.sent.length === 1` with a 1s timeout (5ms interval). Robust against test-runner load spikes; midi.* tests still pass under the same helper.
- **Files modified:** daemon/src/query/query-server.test.ts (driveAsync body only)
- **Verification:** Full daemon suite 514/514 green across two consecutive runs.
- **Committed in:** a9f25ce (part of Task 2 GREEN commit)

**2. [Rule 1 - Bug] Destructure-by-value captured applyCalls at 0**
- **Found during:** Task 2 GREEN isolated test run (D-04 apply PROCEEDS test failed: applyCalls was 0 even though applyPatchOverBridge was called)
- **Issue:** `const { applyCalls } = await makeApplyDeps(...)` snapshots the value at destructure time. The inner `let applyCalls = 0` increments inside the applyPatchOverBridge closure, but the destructured binding in the test never sees those increments.
- **Fix:** makeApplyDeps returns `applyCalls: () => counter.n` (a getter), and the test calls `applyCalls()` instead of `applyCalls`. Same pattern applied to all 4 gate tests using makeApplyDeps.
- **Files modified:** daemon/src/query/query-server.test.ts (makeApplyDeps return type + 2 test sites)
- **Verification:** D-04 PROCEEDS test now asserts applyCalls() === 1 reliably.
- **Committed in:** a9f25ce (part of Task 2 GREEN commit)
