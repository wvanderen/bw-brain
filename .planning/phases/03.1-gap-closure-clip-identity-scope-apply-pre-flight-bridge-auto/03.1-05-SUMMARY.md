## Decisions Made
- **CWD-independence over the established convention.** The existing `check:capabilities` script (and the original draft of this gate) resolves paths relative to CWD, which breaks when invoked via `cd daemon && npm run check:*` (the npm wiring lives in `daemon/package.json`). Because this plan's done-criteria explicitly require `npm run check:bridge-artifact` to exit 0 from `daemon/`, the script anchors all paths to `git rev-parse --show-toplevel`. This is more robust than the `check:capabilities` precedent (which has the same latent CWD bug, pre-existing and out of scope) and establishes a better pattern for future `check-*` scripts.
- **Enumerated SOURCE_PATHS, no runtime glob.** The 9 source paths (7 Java files + ServiceLoader resource + pom.xml) are hardcoded with an audit-trail comment citing `git ls-files`. Avoids false positives from future test files under `bridge/src/test/` and makes the comparison set auditable.
- **TDD split within a single task.** Task 1 is `type="auto" tdd="true"` in a `type: execute` plan. Split into RED (pure functions + self-test, default path stubbed) and GREEN (real integration path) commits to preserve the test(...)→feat(...) gate sequence and prove the decision logic in isolation before wiring git/filesystem access.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed CWD-relative path resolution so `npm run check:bridge-artifact` works from daemon/**
- **Found during:** Task 2 (npm wiring + FAIL-path proof)
- **Issue:** The original script (per the plan's literal `<action>` text) used `resolve("bridge/target/bw-brain.bwextension")` and bare `execFileSync("git", ["log", "-1", ...])`, both of which resolve relative to CWD. When invoked via the plan-mandated `cd daemon && npm run check:bridge-artifact` pattern, the artifact path resolved to `daemon/bridge/target/...` (ENOENT) and the git pathspecs resolved against `daemon/` (no history) — the npm-run invocation the plan requires to exit 0 instead exited 1.
- **Fix:** Compute `REPO_ROOT = execFileSync("git", ["rev-parse", "--show-toplevel"]).trim()` once at module top (with try/catch + exit 1 on failure). Resolve `ARTIFACT_PATH` against `REPO_ROOT` (default) or CWD (override). Pass `cwd: REPO_ROOT` to the `git log` call so pathspecs resolve correctly regardless of CWD. The override, when set, still resolves relative to CWD (testing convenience — typically an absolute `/tmp/` path).
- **Files modified:** `scripts/check-bridge-artifact.mjs` (REPO_ROOT computation + 2 resolution sites)
- **Verification:** Probe (a) `cd daemon && npm run check:bridge-artifact` → exit 0; probe (a2) standalone from repo root → exit 0; probe (b) stale-date from repo root → exit 1; probe (c) missing-artifact → exit 1; probe (b-via-npm) stale-date from daemon/ via npm → exit 1 (FAIL path is also CWD-independent). All 5 probes pass.
- **Committed in:** `2c172c0` (Task 2 commit)
