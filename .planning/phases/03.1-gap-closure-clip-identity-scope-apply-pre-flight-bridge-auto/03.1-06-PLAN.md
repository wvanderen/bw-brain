<objective>
Close the ONE remaining open gap from `03.1-UAT.md` (Tests [4,5], status: failed, severity: major). The M4 safety core WORKS — `bw-edit apply` and `bw-edit revert` correctly REFUSE a wrong-clip targeting BEFORE the bridge round-trip (D-04/D-05 gates fire; no mutation lands on the wrong clip; proven by `daemon/src/query/query-server.test.ts:601-811`). The gap is purely the D-06 DIAGNOSTIC SURFACE: the CLI strips the `wrong_clip_targeted` detail fields (`expectedClipSid`/`actualClipSid`/`hint`) and misreports `stateFreshness` as a hardcoded disconnected stub even when the daemon is live.

Root cause (precisely diagnosed during UAT — do NOT re-investigate, per D-06 surface contract):

1. `daemon/src/cli/query-client.ts:72-77` — `query()` collapses EVERY `ok:false` envelope to `throw new Error(result.error + availableFrom-tail)`, DISCARDING the detail fields and the real `stateFreshness`. The thrown Error carries only a string message.
2. `daemon/src/cli/commands/edit.ts:34-44` — `printConnectionError` (the catch handler for the thrown Error) only has `(e).message`, so it emits a minimal envelope HARDCODED to `stateFreshness:"disconnected"`. Affects preview/apply/revert catch blocks (all three call printConnectionError).

The daemon (`query-server.ts:651-659` apply gate, `767-769` revert gate, `safeSendErr` details handling `865-886`) already emits the fields correctly via `safeSendErr(transport, freshness, "wrong_clip_targeted", { expectedClipSid, actualClipSid, hint })` — PROVEN by `query-server.test.ts:601-811`. The daemon MUST NOT be changed (per D-06 surface contract); this is a CLI-only surfacing fix.

Purpose: Make the producer-facing `bw-edit` CLI honestly relay the daemon's structured refusal so the producer can recover (re-select / re-preview the right clip) and so the Pi `/apply` skill (Plan 03.1-04, `pi-pack/skills/apply/SKILL.md:62-67`) fulfills its `## Wrong-clip targeting (D-04/D-06)` contract — which currently promises fields the CLI strips.
Output: (a) `query-client.ts` gains an exported `DaemonReplyError` carrying the full ok:false envelope (shared fix — benefits every live CLI); (b) `edit.ts` catch blocks surface the envelope verbatim, falling back to the genuine disconnected stub ONLY when the daemon was truly unreachable; (c) `edit.test.ts` gains the CLI-layer proof that wrong_clip_targeted round-trips the three detail fields + the real stateFreshness.
</objective>
