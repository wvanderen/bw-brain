# Phase 04.1: CLAP Capability & Host Evidence Gate — Context

**Gathered:** 2026-08-06
**Status:** Ready for execution

<domain>
## Phase Boundary

Phase 04.1 is an evidence gate, not the Hybrid CLAP Companion product. It establishes a reproducible isolated capability toolchain, probes real CLAP/Bitwig and Controller API behavior, audits the proposed Pi package without installing it, and records approved answers to Q1–Q4 for Phase 04.2 planning.

The product decisions D-01 through D-16 moved to Phase 04.2 and are explicitly out of Phase 04.1 execution scope. Phase 04.1 must not create production schemas, peer routing, persistent plug-in identity, daemon project/session services, Pi integration, real-time telemetry/scheduling, proposal approval, journal integration, or hosted product UI.
</domain>

<decisions>
## Locked Gate Decisions

- **D-GATE-01 [GATE-01] — Isolated immutable toolchain:** Use CMake >=3.22 with explicit missing-tool recovery. Pin CLAP, JUCE, the adapter, and clap-validator to reviewed immutable SHAs with source/license evidence. Configure capability work only in `clap/build-capability`, build the validator at `clap/build-capability/tools/clap-validator/clap-validator`, and keep `clap/build` absent so capability and product caches cannot leak into each other.

- **D-GATE-02 [GATE-02] — Bitwig/CLAP capability evidence:** Build only a throwaway `clap/spike/*` bundle and dependency-light CTest probe. Prove automated and live Bitwig behavior for transparent mono/stereo float/double pass-through, MIDI sample offsets, GUI lifecycle, state reopen/copy, parameter/device-panel categories, optional track-info, transport/lifecycle callbacks, and supported hosting modes. Record absence as evidence rather than inferring support. Do not select a product fallback until live evidence is approved.

- **D-GATE-03 [GATE-03] — Read-only controller/project metadata evidence:** Probe definitive project/document identity, Save As observability, and selected-device context through a package-private read-only `PullHandlers` request on the existing controller TCP. The probe must not add instance-link authority or mutation primitives, must leave `apply.patch` unchanged, and must represent unavailable fields explicitly instead of deriving identity from names.

- **D-GATE-04 [GATE-04] — Non-installing Pi audit and approved research resolution:** Inspect the exact `@earendil-works/pi-coding-agent` registry metadata and tarball without installing it or executing lifecycle scripts. A human approves or rejects the exact package/version. Q1–Q4 change from open to `## Open Questions (RESOLVED)` only after dated automated/live/package evidence selects explicit outcomes. Completing this gate makes `$gsd-plan-phase 04.2` the next action.

## the agent's Discretion

- Choose the CMake mechanism used to fetch/build pinned dependencies, provided immutable lock data and deterministic paths remain inspectable.
- Choose the minimal package-private Java probe seam, provided the existing controller transport and mutation switch remain unchanged.
</decisions>

<specifics>
## Required Evidence Outcomes

1. Q1 records whether track-info is present through Bitwig and the adapter; Phase 04.2 will treat it as hint-only if present or use controller-confirmation-only if absent.
2. Q2 records whether definitive project identity/Save As evidence exists; Phase 04.2 will use detected-then-confirmed fork flow if present or an explicit `session.fork` action if absent.
3. Q3 records compact-panel support for status and non-recording actions; Phase 04.2 will use native status/actions if supported or read-only status parameters plus momentary triggers otherwise.
4. Q4 records approval or rejection of the exact Pi package version/layout; Phase 04.2 planning must honor that result rather than silently substituting a package.
</specifics>

<deferred>
## Moved to Phase 04.2 / Out of Phase 04.1 Scope

- All product behavior governed by D-01 through D-16.
- Production CLAP target and `clap/build` artifacts.
- Dedicated peer schemas, routing, authorization, and multi-instance services.
- Persistent production instance identity and daemon rekey behavior.
- Project/session/fork services and installed Pi runtime integration.
- Aggregate telemetry, real-time scheduler, note ledger, proposal/approval delegation, and product UI.

## Product Ideas Still Deferred Beyond the Phase 04.2 Boundary

- Autonomous continuous-generative mode or persistent trust windows.
- Proactive background Pi analysis or suggestions.
- Raw audio capture, audio snippet retention, audio mastering, or stem processing.
- Replacing the controller extension with CLAP or using CLAP to mutate existing Bitwig clips directly.
- Cross-project global Pi memory; project copies fork rather than share active session history.
</deferred>
