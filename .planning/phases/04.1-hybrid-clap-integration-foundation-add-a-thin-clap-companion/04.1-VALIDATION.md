# Phase 04.1 — Capability-Gate Validation Strategy

This validation contract covers Phase 04.1 only: GATE-01 through GATE-04. Product schemas, routing, identity, sessions, real-time scheduling, journal integration, and UI belong to Phase 04.2 and are absent here.

## Test Infrastructure

| Property | Value |
|---|---|
| Framework | CTest for the throwaway capability probe; JUnit 5 for the read-only Controller API probe |
| Capability build | `clap/build-capability` only |
| Product build | `clap/build` MUST remain absent during these plans |
| Validator | Pinned source build at `clap/build-capability/tools/clap-validator/clap-validator` |
| Quick command | `ctest --test-dir clap/build-capability -R capability_probe --output-on-failure` |
| Full gate command | `cmake --build clap/build-capability --config Release --target bw-brain-capability capability_probe_test clap-validator && ctest --test-dir clap/build-capability --output-on-failure && clap/build-capability/tools/clap-validator/clap-validator validate clap/build-capability/bw-brain-capability.clap` |

## Sampling Rate

- After Plan 01 Task 1: preflight, configure, pinned validator build, and assert no product cache.
- After Plan 01 Task 2: structural evidence check only; package stays uninstalled.
- After Plan 02 Task 1: capability CTest, pinned validator, and no product cache.
- Plan 03 Task 1: read-only Java probe with unchanged mutation/transport authority.
- Plan 03 Task 2: blocking live Bitwig/package evidence plus exact research-heading gate.
- Plan 04 Task 1: deterministic lock-free MIDI offset capture/presentation regression, isolated rebuild, and validator.
- Plan 04 Task 2: blocking live non-zero offset equality proof followed by gate and roadmap reconciliation.
