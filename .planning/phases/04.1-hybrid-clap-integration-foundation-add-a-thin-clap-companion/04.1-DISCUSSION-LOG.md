## First Useful Plug-in Experience

| Decision | Alternatives considered | Selected |
|----------|-------------------------|----------|
| Dominant experience | Focused workspace; full agent console; analysis dashboard | Focused workspace ✓ |
| Layout | Three-pane flow; conversational feed; fixed split view | Three-pane flow ✓ |
| Closed-window controls | Essential device controls; status only; full compact workflow | Essential device controls ✓ |
| Startup | Connect and orient; quick automatic analysis; dormant until Connect | Connect and orient ✓ |

**User's choice:** A focused three-pane musical workspace with essential compact controls and a quiet ready state.
**Notes:** The hosted UI should not reproduce Pi's terminal or trigger automatic analysis.

## Real-time Boundary

| Decision | Alternatives considered | Selected |
|----------|-------------------------|----------|
| Collection | Continuous local telemetry/on-demand reasoning; explicit windows; continuous suggestions | Continuous local telemetry/on-demand reasoning ✓ |
| Data leaving plug-in | Aggregates only; aggregates plus snippets; raw rolling audio | Aggregates only ✓ |
| MIDI output | Approved material only; monitor-only; continuous generative mode | Approved material only ✓ |
| Disconnect behavior | Transparent fail-safe; finish phrase; immediate hard stop | Transparent fail-safe ✓ |

**User's choice:** Keep signal observation local and lightweight, send only bounded features, reason on demand, and emit only explicitly approved live MIDI.
**Notes:** Original signal remains transparent and safe if the daemon or Pi disappears.

## Instance and Session Model

| Decision | Alternatives considered | Selected |
|----------|-------------------------|----------|
| Pi topology | One project session/many contexts; one session per instance; global session | One project session/many contexts ✓ |
| Track linking | Auto-discovery plus confirmation; fully automatic; manual every time | Auto-discovery plus confirmation ✓ |
| Active target | Focused instance with explicit scope; Bitwig selection; Pi inference | Focused instance with explicit scope ✓ |
| Persistence | Project-local safe forks; shared lineage; ephemeral sessions | Project-local safe forks ✓ |

**User's choice:** One daemon-owned project session with persistent, confirmed per-track instance identities and explicit focused-instance scope.
**Notes:** Save As forks the project session; plug-in duplication creates a new instance identity within the same project session.

## Approval Flow Inside Bitwig

| Decision | Alternatives considered | Selected |
|----------|-------------------------|----------|
| Project edit authority | UI approves/controller applies; direct CLAP apply; external-only approval | UI approves/controller applies ✓ |
| Live audition launch | Arm then musical boundary; immediate; transport-start only | Arm then musical boundary ✓ |
| Approval lifetime | One-shot scope-bound; session trust window; persistent permission | One-shot scope-bound ✓ |
| Global Stop | Stop generated behavior/preserve song; stop and revert session; immediate panic/disconnect | Stop generated behavior/preserve song ✓ |

**User's choice:** Keep the existing controller mutation trust spine, use exact one-shot approvals, launch armed MIDI at musical boundaries, and keep Stop separate from project revert.
**Notes:** No approval survives a proposal revision or target change.
