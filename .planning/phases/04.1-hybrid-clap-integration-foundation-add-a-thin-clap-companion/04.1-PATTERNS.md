# Phase 04.1: Hybrid CLAP Integration Foundation - Pattern Map

**Mapped:** 2026-08-06
**Scope:** D-01 through D-16 (locked)
**Files analyzed:** 31 existing implementation/test/config files plus phase artifacts
**Analogs found:** 16 / 24 inferred file groups; native CLAP/C++/CMake groups have no local analog

## Planner Summary

Phase 04.1 is an additive integration, not a replacement architecture. Preserve three existing authorities:

1. `daemon/src/runtime/boot.ts` remains the composition root and daemon authority.
2. `daemon/src/query/query-server.ts` plus `daemon/src/patch/*` remain the only existing-project approval/apply/revert trust spine.
3. `bridge/src/main/java/com/bwbrain/bridge/PullHandlers.java` remains the sole Bitwig project mutation adapter.

Create a dedicated CLAP peer endpoint. Reuse JSON-Lines framing, schema-at-boundary validation, UUID correlation, loopback guards, bounded queues, and explicit failure responses, but do **not** attach plug-ins to `TcpServerTransport`: its `send()` broadcasts to all sockets and its inbound callback erases connection identity.

## Pattern Assignments

### Dedicated daemon CLAP peer server (`daemon/src/peers/peer-server.ts`)

**Analogs:** `daemon/src/transport/tcp.ts`, `daemon/src/protocol/line-buffer.ts`, `daemon/src/protocol/reader.ts`

Copy the hard loopback bind and atomic JSON-Line write convention from `tcp.ts:24-25,50-81,88-97`:

```ts
const LOOPBACK_HOST = "127.0.0.1";
if (host !== LOOPBACK_HOST) throw new Error(/* refuse widened bind */);
this.server.listen(this.port, this.host);
const line = JSON.stringify(msg) + "\n";
socket.write(line);
```

Copy framing separation from `line-buffer.ts:30-49`: buffering only; no JSON parsing or validation in the buffer.

Copy the receive pipeline from `reader.ts:32-67,126-169`: compile Ajv once, then `LineBuffer -> JSON.parse try/catch -> schema validation -> bounded enqueue -> microtask drain`. Observational telemetry may coalesce/drop; requests, approve, arm, and Stop must never silently drop.

**Required divergence:** `tcp.ts:38-41,63-74,88-97` deliberately merges inbound sockets into one handler and broadcasts outbound messages. The new server must instead construct one `PeerConnection` per socket, retain `connectionId`, own a per-connection `LineBuffer` and queue, and expose only `sendTo(peerId, envelope)`. Add a negative test proving controller envelopes and another instance's proposal never reach a CLAP peer.

### Peer registry, routing, and correlation (`daemon/src/peers/*`)

**Analogs:** `daemon/src/protocol/correlator.ts`, `daemon/src/patch/candidate-store.ts`, `daemon/src/runtime/dispatcher.ts`

Copy correlation lifecycle from `correlator.ts:66-114,124-155`:

```ts
const id = randomUUID();
const timer = setTimeout(() => { pending.delete(id); reject(/* timeout */); }, timeout);
pending.set(id, { resolve, reject, timer });
try { transport.send(envelope); }
catch (e) { clearTimeout(timer); pending.delete(id); reject(e); }
```

Late/unknown IDs are logged and dropped, never thrown (`correlator.ts:120-133`). Disconnect must reject all pending work and clear timers (`142-155`). For CLAP, key pending calls by both connection/peer and request ID; an ID from peer B must not resolve peer A's request.

Use `CandidateStore`'s bounded insertion-ordered `Map` pattern (`candidate-store.ts:48-76`) for peer leases and ephemeral approval/proposal records, including explicit eviction. Do not use it literally for live connections: registry cleanup must also occur on socket close and revoke focus/approval leases.

Route by an explicit discriminated message type, following the total switch and structured unknown-request arm in `PullHandlers.java:155-188` / `runtime/dispatcher.ts`. Authorization must precede dispatch: peer kind and confirmed project/instance scope determine allowed message families.

### Handshake and schemas (`schemas/clap/*.schema.json`, `scripts/gen-types.mjs`)

**Analogs:** `schemas/protocol/handshake.schema.json`, `schemas/protocol/envelope.schema.json`, `daemon/src/protocol/reader.ts`, `scripts/gen-types.mjs`

Follow Draft 2020-12, absolute `https://bw-brain.local/...` `$id`, `additionalProperties:false`, discriminator enums, and conditional required fields. Extend the hello contract concept to include `peerKind`, persistent `instanceId`, capabilities, protocol version, and daemon-issued connection identity; do not weaken the current controller schema in place unless backward compatibility is demonstrated.

Runtime convention is compiled-once Ajv (`reader.ts:32-67`; `patch-schema.ts:25-68`), never per message. Register cross-file schemas before compiling the envelope.

Extend `scripts/gen-types.mjs` at its schema-root list (`31-41`). Generation already builds a shared `$id` registry and resolves cross-directory refs (`205-238`). Add `schemas/clap` deterministically, keep generated TS under `daemon/src/gen`, and add schema/codegen drift tests beside `daemon/src/protocol/schemas.test.ts`.

For C++, no local generator exists. Planner should require one of two explicit paths: generate checked C++ DTOs from the same schemas, or implement a narrow decoder with field/type/range/count limits and golden fixtures shared with daemon tests. Never rely on unchecked JSON casts.

### Daemon composition (`daemon/src/runtime/boot.ts`)

**Analog:** same file, especially `boot.ts:160-175,196-300,302-365`

Instantiate peer server, registry, session manager, proposal stores, and Pi adapter in `boot.ts`; inject narrow interfaces into handlers. Follow lazy closure/thunk wiring used for the replaceable correlator (`172-175,280-300,335-365`) so reconnect/fork can replace runtime objects without stale captures.

Copy lifecycle behavior from `302-326`: socket transition updates health, rejects pending work, constructs fresh correlation state, and refreshes authoritative state on reconnect. Generalize health by peer/project/instance; do not overload the controller's single `StaleWatchdog` status.

Persistence follows debounced async writes (`177-194`) and project-local paths. Do not perform sync or per-event disk I/O. Project-session identity cannot be inferred from `process.cwd()` or display name; create explicit registry/lineage data and a confirmed Save As fork flow.

### Project session and Pi integration (`daemon/src/sessions/*`)

**Local analogs:** `daemon/src/state/intent-store.ts`, `roles-store.ts`, `state-cache.ts`, `analyzer-registry.ts`; `pi-pack/README.md`; `pi-pack/skills/*`

There is no embedded Pi runtime locally. Preserve the established boundary: `pi-pack/README.md:1-3,30-42` declares the `bw-*` CLI as the stable contract and Pi as a UX wrapper. The SDK adapter must expose only approved bw-brain operations that reach the same daemon handlers as CLI commands; do not provide a second direct mutation API.

Follow existing stores: project-local explicit path passed to constructor, schema validation on load/write, atomic temp-in-destination-directory rename, and test-injected temporary paths. One manager owns one Pi session per project and routes streamed events to focused confirmed instances. Rebind subscriptions after resume/fork/switch and dispose them on shutdown.

Create a fake `PiRuntime` interface for tests. No daemon tests should call a model, registry, or network. Wave 0 must verify the actual SDK package/version/postinstall before adding it.

### Instance/project identity and controller confirmation

**Analogs:** `bridge/.../ClipSid.java`, `daemon/src/state/reconcile.ts`, `BridgeExtension.java`

Copy the identity-helper discipline from `ClipSid.java:22-33,65-80`: pure, dependency-light, deterministic, pattern-valid identifiers with tests. But do not copy its heuristic inputs for CLAP authority; D-10 requires persistent instance ID plus daemon lease collision detection and one-time controller/user confirmation.

Use separate state machines:

- instance lease: `connecting -> active -> disconnected`, with simultaneous duplicate ID causing daemon-issued rekey;
- link: `unconfirmed -> confirmed(trackSid/device context) -> stale/unlinked`;
- project session: `unbound -> active -> fork-required -> forked`.

Track names and optional CLAP track-info are hints only. Unconfirmed instances may show status but must fail prompt, approve, apply, and arm requests closed.

Modify the Java surface additively: observer callbacks enqueue O(1) messages and never block (`Outbox.java:56-62`); connector work stays on daemon threads and self-heals (`BridgeExtension.java:114-129,177-220`). Any new identity/link request belongs in `PullHandlers`' total request switch and should return structured response envelopes.

### Proposal, approval, pre-flight, and existing-project apply

**Analogs:** `candidate-store.ts`, `query-server.ts`, `patch-history.ts`, `inverse-ops.ts`

Model a proposal revision as a bounded ephemeral candidate. Copy `CandidateStore`'s daemon-minted UUID, bounded map, and explicit post-success eviction (`candidate-store.ts:53-76,79-105`). Extend scope to `{proposalId, revision/contentDigest, projectId, instanceId, clipSid?, kind}`. Any revision or target change mints a new revision and invalidates prior approval.

The CLAP UI approval handler must adapt into, not duplicate, the existing sequence in `query-server.ts`:

1. Validate patch and compute preview/risk (`615-675`).
2. Load exact candidate (`695-700`).
3. Recheck live target before bridge round-trip (`701-724`).
4. Enforce confirmation/risk (`725-743`).
5. Freeze inverse at apply time (`745-746`).
6. Call injected controller bridge adapter (`747-764`).
7. Append history and evict candidate only after successful mutation (`765-788`).

Approval adds stricter project/instance/revision checks before step 2 and atomically consumes its grant. It must call the shared edit operation, not `applyPatchOverBridge` directly.

Revert stays separate from global Stop. Preserve `query-server.ts:1170-1270`: verify live clip, replay frozen inverses through the same bridge path, append the revert, and prevent double revert. Preserve `inverse-ops.ts:89-121` pure reverse-and-invert semantics and `patch-history.ts:96-135,143-178` append/skip-malformed/atomic-stamp conventions.

Use the one structured error helper pattern (`query-server.ts:1294-1327`), extending it rather than creating parallel error formats. Approval failures should include exact machine-readable expected/actual scope and remediation hints.

### Java controller mutation bridge

**Analog:** `bridge/src/main/java/com/bwbrain/bridge/PullHandlers.java`

Do not add CLAP mutation APIs to Java. Preserve the three-primitive bridge surface and its test seam:

```java
switch (opType) {
  case "add_note" -> ...;
  case "remove_note" -> ...;
  case "update_note_field" -> ...;
  default -> failed++;
}
```

This is `PullHandlers.java:286-360`; the live Bitwig adapter is isolated behind `NoteStepWriter` (`271-306,386-398`). All semantic proposal meaning remains daemon metadata. Per-operation failures are counted and returned, not thrown out of the handler.

Any controller-assisted link/fork metadata should be read-only/pull or confirmation signaling. Existing clip/project state continues to mutate only through `apply.patch`.

### CLAP peer client (`clap/src/peer/*`)

**Analogs:** `BridgeExtension.runConnectorCycle`, `Outbox`

Copy the lifecycle shape, not Java implementation details: retry loopback connect; start independent reader/writer work; detect quiet socket loss from the reader; stop, clear stale outbound observational data, reset, and reconnect (`BridgeExtension.java:114-129,177-220`).

Copy non-blocking producer/worker separation from `Outbox.java:56-94`: producers enqueue; one worker owns socket writes. For CLAP, audio-thread producers must use a fixed-capacity audited SPSC queue, not Java's unbounded blocking queue. Only telemetry may drop/coalesce. Approve/arm/Stop must be acknowledged or explicitly failed.

Never parse JSON, allocate, lock, log, or touch sockets from `process()`.

### Native real-time plane (`clap/src/rt/*`, `PluginProcessor.*`)

**No local implementation analog.** The repository has no C++, DSP callback, lock-free queue, sample-offset output, CMake, JUCE, or CLAP lifecycle code.

Local conventions that still govern the seam:

- pure logic extracted behind narrow adapters, as in `inverse-ops.ts` and `PullHandlers.NoteStepWriter`;
- bounded memory/backpressure, as in `reader.ts:69-110,150-169`;
- explicit lifecycle cleanup and reconnect, as in `BridgeExtension.runConnectorCycle`;
- deterministic IDs and state transitions with unit tests;
- fail closed for generated behavior while preserving original signal.

Required native modules/tests should cover bit-transparent audio/MIDI pass-through, fixed-capacity queue overflow, bounded aggregate features, immutable phrase handoff, sample-sorted events, beat/bar boundary math under variable blocks, owned-note cleanup, transport jumps, Stop, disconnect, reset, deactivate, and phrase replacement. Raw audio must never appear in schemas, queues crossing the process boundary, logs, or persistence.

### Hosted UI and shared state model (`PluginEditor.*`, `model/UiState.*`)

**No local production UI analog.** Existing Pi skills define output contracts, not component architecture.

Preserve one explicit reducer/state machine shared by full editor and compact controls:

`ready -> analyzing -> proposalPending -> armed/countdown -> playingGenerated -> stopping -> ready`, with `disconnected` reachable from every state.

Target project/track/instance must be part of every state snapshot and visible in the context strip. Proposal drawer appears only for a concrete revision. Focus change invalidates scope-bound approvals. Quiet startup performs connection/identity only and must have a test asserting zero Pi prompt/analyze calls.

The three-pane layout (context strip, conversation, conditional proposal drawer) is locked by D-01/D-02. Device-panel actions and full editor must dispatch the same commands into the same reducer, not maintain duplicate state.

## Testing Patterns

### Daemon tests

Use colocated `*.test.ts`, Vitest, in-memory fakes, and dependency injection. `daemon/vitest.config.ts:15-23` defines eligible roots; add new daemon tests under `src/**` and explicitly include any new cross-root contract fixtures to avoid vacuous green runs.

Copy `correlator.test.ts` patterns: fake transport captures sent envelopes; fake timers assert timeout cleanup; unknown/duplicate IDs do not throw; close rejects all outstanding work. Extend to two or more peers and assert strict routing isolation.

Extend `query-server.test.ts` rather than creating a second apply suite. Required cases: wrong project, instance, clip, revision, consumed token, focus switch, unconfirmed link, bridge failure, partial apply, journal equivalence with CLI, and Stop not invoking revert.

### Java tests

Use JUnit 5 and package-private pure seams; no Mockito. `PullHandlersApplyPatchTest.java:11-16,29-49` injects a small recording functional interface and `82-166` pins success, partial failure, unknown operations, and semantic-metadata ignorance. New controller identity helpers should follow this style.

### Native tests

No local native test convention exists. Establish CTest plus dependency-light native/JUCE executables in Wave 0. Keep host APIs behind thin adapters so RT algorithms run without Bitwig. Add allocation instrumentation and deterministic property/table tests; validator/live-host checks supplement rather than replace unit tests.

## Shared Patterns

### Boundary Validation

Every process boundary is schema validated before dispatch. Schemas are closed (`additionalProperties:false`), versioned, and generated into committed TS. C++ decode additionally enforces frame size, field lengths, array counts, MIDI ranges, telemetry cadence, and phrase duration/count bounds.

### Failure Semantics

User intent is never silently lost. Request/approve/arm/Stop receives an ack or structured error. Observational telemetry alone may coalesce/drop under pressure. Malformed/late/unknown observational input is dropped without crashing the daemon.

### Authority

- Daemon: project/session/focus/proposal/approval/routing authority.
- Controller: only existing Bitwig project mutation adapter.
- CLAP: signal-local observation and playback of an exact approved live phrase.
- Pi: external reasoning/session provider, accessed through restricted bw-brain operations.
- CLI: stable automation contract and fallback UX.

### Persistence

Project/session/journal data is daemon-owned and project-local. Plug-in state persists only instance-local identity/settings. Save As forks session lineage explicitly; duplication rekeys the later simultaneous instance. Atomic writes use a temp file in the destination directory followed by rename.

### Health and Fail-safe

Health is explicit per controller, Pi session, and CLAP instance. Disconnect makes the plug-in dry pass-through, cancels generated future events at a safe boundary, emits owned note-offs, disarms approval, and visibly reports disconnected. It never changes original audio/MIDI or silently reverts journaled edits.
